# Every row the Quick Menu builds, per product. A decision record, like
# SHARED_FUNCTIONS.txt and DIVERGENT_FUNCTIONS.txt.
#
# Why this file exists
# --------------------
# The fingerprint gate cannot see the Quick Menu. The two trees build rows
# differently -- standalone stores id and label and resolves the value later,
# the companion carries value and action on the row -- and that difference drags
# every QuickMenu* function below the 0.75 threshold. Twelve functions and about
# 1,150 lines therefore sit unmeasured, in the one part of the program a user
# drives directly.
#
# Nothing about a broken row fails to compile. AutoHotkey resolves a `case` that
# no longer exists by falling through, so a row whose handler was deleted still
# renders, still selects, and does nothing. That is the failure this file makes
# loud, and it is the reason the inventory is recorded rather than derived: a row
# that DISAPPEARS is invisible to any check that only reads the code as it is.
#
# Format
# ------
#   <product> <rowId>              a row the product builds
#   <product> dynamic:<name>       a handler reached through a variable rather
#                                  than a literal row, so the "every handler has
#                                  a row" direction does not flag it
#
# Ids carrying a colon -- layout:, taskWindow:, gamescore:, toggle:, page: --
# are families resolved by prefix and are deliberately not listed one by one.
#
# Delete a line in the same commit that deletes its row. An entry with no row,
# and a row with no entry, both fail the build.
#
# What this file does NOT see
# ---------------------------
# Ids, not actions. The companion dispatches on the ACTION a row carries, and
# for most rows the action and the id are the same word -- but only by
# convention. The MAIN page's Mouse Mode row had id qPersistentMouse and action
# "toggle:mouseMode", nothing answered to mouseMode, and the row rendered,
# selected and did nothing. Both directions of the check above were satisfied
# the whole time: the row existed and so did its entry here.
#
# So the companion's toggle actions are now built from the row id, and
# Validate-SteamShell-XFE.ps1 enumerates every literal "toggle:<name>" it can
# find and requires each to be either qPersistentMouse or a QuickMenuToggleTable
# id. A row inventory cannot check the wiring behind a row; that rule can.
